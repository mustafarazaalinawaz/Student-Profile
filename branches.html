Working with branches

A branch gives a line of work its own name, so changes can be developed and reviewed without immediately changing the default branch.

What a branch does

Git branches are movable references to commits. A developer can create a branch, make commits on it, and later merge those commits into another branch such as main.

Branches make it easier to isolate a feature, experiment, or fix. They do not create a separate copy of the entire project history.

Useful commands

  • git branch lists local branches.
  • git switch -c feature-name creates and switches to a branch.
  • git switch main switches to an existing branch.
  • git merge feature-name merges that branch into the current branch.
  • git branch -d feature-name deletes a branch after its work is merged.

A simple workflow

  1. Create a focused branch from the branch you intend to update.
  2. Make a small, meaningful change and commit it.
  3. Push the branch and review the changes.
  4. Merge locally or open a pull request for review.
